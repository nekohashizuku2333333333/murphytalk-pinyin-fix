## 靠你找到的源码，问题彻底搞清楚了

之前我判断"简拼是引擎级大改、不敢碰"。看了源码后发现**没那么可怕**，原因有两点：

**① 引擎其实"愿意"接受单声母。**
`set_key("n")` 会把 `n` 解析成 `(声母=n, 韵母=空)` 这个键，然后拿去问"校验器"合不合法。而校验器 `scim_default_pinyin_validator` 是个**默认构造、位图全 0** 的对象——它的判定逻辑是"位图为 0 即合法"，所以**除了全空键，它接受任何键**，包括单声母 `(n,空)`。也就是说，引擎查 `n` 时是拿着 `(n,空)` 去单字表里找的，**只是表里没有这个键的词条**，所以查无结果。

**② 真正拦路的是"加载器"。**
单字表加载函数 `PinyinTable::input()` 里有一句：
```cpp
if (entry.get_key().get_final() == ZeroFinal) {   // 韵母为空
    std::cerr << "Invalid entry";                  // 直接丢弃！
} else { ...加入表... }
```
所以哪怕我在词表里写上"n 对应哪些字"，加载时也会因为"韵母为空"被**当成非法条目扔掉**。

## 这次的修法（1 字节引擎补丁 + 词表数据）

- **引擎补丁（仅 1 字节）**：把上面那句判断的分支 `bne`（韵母≠空才加入）改成无条件 `b`（一律加入），于是"韵母为空"的单声母词条不再被丢弃。
  - 位置：`PinyinTable::input` 内，文件偏移 `0x1A3EF`，`0x1A → 0xEA`。
  - 反汇编已确认变成 `b 0x1a430`（直接走"加入"分支，跳过报错丢弃）。
- **词表数据**：给 23 个声母各加一条"简拼词条"，列出该声母下**最常用的 40 个字**（按字频排序）。表头计数 410→433。
  - 加载器加载完会自动重排序，所以追加是安全的；原有 410 条一条没动。

打补丁后，键入单个字母就能出候选，例如：
- `n` → 你 那 能 年 女 内 呢 男 难 南 拿 …
- `d` → 的 大 到 都 对 地 道 电 …
- `sh` → 是 上 时 说 生 手 …
- `w` → 我 为 无 王 问 万 …
- `y` → 一 有 也 用 又 以 …

（`a e o` 这类零声母的单字母本来就能出，因为它们本身就是完整韵母。）

## 说清楚边界（诚实交代）
- **目前简拼是"单字母出单字"**：打 `n` 出一串以 n 开头的**单字**（按字频，共 40 个，翻页看更多）。
- **多字母简拼（如 `nh`→你好）暂不支持**：那需要另给短语表补一批"简拼键"的词条（`nh`、`bj`…）。能做，但要额外造数据；你要的话我加。
- 单声母候选我只放了每个声母**前 40 个高频字**（够日常，不至于把候选表撑爆）。想要更多/更少，或想调某个字靠前，都能改。

```sh

cp /opt/Qtopia/plugins/inputmethods/libmurphypinyin.so.0.03 ~/libmurphypinyin.so.0.03.bak
cp -r /home/zaurus/.murphytalk ~/.murphytalk.bak
ipkg install -force-reinstall murphytalk.pinyin_0.03_arm_full.ipk
# 重启 Qtopia（或注销重进）
```
