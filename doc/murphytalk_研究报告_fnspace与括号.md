## 一、先回答括号问题（结论明确，可直接采用）

**左括号 / 右括号（以及方括号、花括号）都不在这个全角表里。** 按下它们时会原样输出**半角** `(` `)` `[` `]` `{` `}`，不会变成全角。

### 依据
全角标点的**唯一**映射发生在 `send_hanzi_mark(this, keycode)`（`0x17118`）。
它是一张 **switch 跳转表，只覆盖 keycode `0x2C`–`0x3F`** 这一段
（`sub r1,r1,#0x2c; cmp r1,#0x13; addls pc,...`），表里真正有映射的只有 6 个键：

| 按键 | keycode | 输出全角 | 码位 |
|---|---|---|---|
| `,` | 0x2C | ， | U+FF0C |
| `.` | 0x2E | 。 | U+3002 |
| `:` | 0x3A | ： | U+FF1A |
| `<` | 0x3C | 《 | U+300A |
| `>` | 0x3E | 》 | U+300B |
| `?` | 0x3F | ？ | U+FF1F |

（这 6 个常量就躺在函数尾部的常量池 `0x171D8`–`0x171EC`，已逐字节核对。）

括号的 keycode 全部落在这段之外：

| 按键 | keycode | 是否在表 | 现状 |
|---|---|---|---|
| `(` | 0x28 | 否（< 0x2C） | 半角原样输出 |
| `)` | 0x29 | 否（< 0x2C） | 半角原样输出 |
| `[` | 0x5B | 否（> 0x3F） | 半角原样输出 |
| `]` | 0x5D | 否（> 0x3F） | 半角原样输出 |
| `{` | 0x7B | 否（> 0x3F） | 半角原样输出 |
| `}` | 0x7D | 否（> 0x3F） | 半角原样输出 |

在主分派 `GetKey` 里，这些键既不是数字/字母/空格/方向/退格，就一律落到
`send_hanzi_mark` → 因超出 0x2C–0x3F 范围返回 0 → 交给 `SendKey` 原样送出。所以它们是半角。

> **能不能加进去？** 能，但不是「翻一个字节」那种小补丁。跳转表只有 0x2C–0x3F 这 20 个槽，
> `(` `)` 在下界之外、`[ ] { }` 在上界之外，要新增就得改判断范围 + 挖一小段 code cave 放新分支和新常量。
> 如果你要，我可以做一版把括号也映射成全角的：
> 常见方案是 `(`→（(U+FF08)、`)`→）(U+FF09)；`[`→【(U+3010)、`]`→】(U+3011)（或「」U+300C/D）；`{` `}`→｛｝(U+FF5B/D) 或 〔〕。
> 你定映射，我来改。

## 二、Fn+Space 切换出「abc」——问题定位

### 这个输入法到底是怎么装进系统的
`libmurphypinyin.so` 同时扮演两个角色：

1. **一个标准 Qtopia 输入法插件**（`QPinyinImpl`，实现 `InputMethodInterface`）：
   - `name()` 返回的显示名是 **"MurphyTalk"**（字符串在 `0x3842C`，分组 `"InputMethods"` 在 `0x38438`）。
   - `inputMethod()` 负责创建并返回那个候选窗口 `QPinyinFrame`。
   - 这就是它出现在系统「输入法选择/切换」列表里的身份。

2. **一个全局键盘过滤器**（`QPinyinFrame` 同时继承 `QWSServer::KeyboardFilter`，基类子对象在 +0xBC）。
   关键：**构造函数里就直接** `grabKeyboard()` + `setKeyboardFilter(this)` 装上了这个全局过滤器
   （`0x15B64`–`0x15B6C`）。也就是说——**只要这个插件对象一被创建，它就开始截获整台机器的按键**，
   拼音处理都在 `filter()`→`GetKey()` 里完成。

### 为什么按 Fn+Space 会冒出「abc」
- **Fn+Space「切换输入法」这个动作本身，是 Qtopia 系统（qpe）在管的，不在这个 .so 里。**
  我把整个插件翻了一遍：它**没有任何一处**代码去识别「切换输入法」这个键——
  `GetKey` 认识的键只有 数字0-9、字母a-z/A-Z、空格、方向键、退格、Shift(0x1020)、Tab(0x1001)、Esc(0x1000)，
  其余全部丢给 `send_hanzi_mark`。没有「IME 切换键」的概念。
- 所以按 Fn+Space 时，是**系统在它注册的输入法之间轮换**：`MurphyTalk` ↔ 系统自带的 **「abc」（内置拉丁/键盘输入法）** ↔ …
  轮到「abc」时，你看到的就是系统默认输入法，而不是这个拼音。

一句话：**「abc」是系统另一套输入法**，不是这个拼音插件画出来的东西
（二进制里根本没有 "abc"/"英"/"中" 之类的字样，全角/候选逻辑也不产生它）。
这个插件管不到「Fn+Space 该轮到谁」——那是 qpe 的事。

### filter() 的开关逻辑（供参考，也是修复的落点）
```
filter(uni, keycode, modifiers, isPress, autoRepeat):
    if (this->state@0x38 & 8)  return false;   // 处于某状态位时：直接放行给系统（→ 于是走到 abc）
    if (!isPress)              return false;
    if (this->mode@0x140 != 0) { ...Tab 切到的直通模式... }
    else                        return GetKey(this, uni, keycode);   // 正常拼音
```
- 过滤器一旦装上（构造时）就**永不卸载**——`hide()` 只做 `ungrabKeyboard()` + 清拼音串，
  **没有** `removeKeyboardFilter`（整个 .so 里根本没引入这个符号）。
  → 好消息：这意味着 `filter()` 对**每一次按键**、在插件整个生命周期内都会被调用到。

## 三、Fn+Space 有没有可能「只在这个拼音里开/关」——可行方案

因为过滤器是常驻的，理论上**可以**把「切换」这件事收进插件自己手里，做到：
按 Fn+Space → 由插件自己 show()/hide() 拼音候选窗，并**把这个键吞掉**，让 qpe 根本收不到、也就不会轮到「abc」。

- `show()`（`0x17768`）= `QWidget::show` + `grabKeyboard` + 重新 `setKeyboardFilter`；
- `hide()`（`0x1778C`）= `QWidget::hide` + `ungrabKeyboard` + 清状态。
- 在 `filter()` 最前面加一段：`if (是 Fn+Space 且 isPress) { 在 show/hide 间切换; return true; }`
  即可实现「开/关的始终是这个拼音」。

**但这一步卡在一个我无法从二进制推断出来的关键信息上：Fn+Space 在你这台机器上到底送出什么按键码。**
- 键盘丝印上 Space 的橙色功能是「Symbol」，可你说 Fn+Space 是「切换输入法」——说明它在你这台机上被 ROM/键盘层绑成了某个特定 keycode（或 unicode）。
- 这个值不在 .so 里（在系统键盘映射 / qpe 里），**猜错就会吞错键、甚至打不了字**。输入法属于「打错就很麻烦」的东西，所以我不想瞎猜着改。

### 另一条不改这个 .so 的思路
如果你的真实诉求只是「别再轮到 abc」，更稳的办法其实是**在系统侧把那个内置「abc」输入法从切换列表里去掉/禁用**
（改 qpe 的输入法配置，或移掉对应的内置输入法插件），这样 Fn+Space 就只在「MurphyTalk ↔ 关」之间切。
这不属于改这个 ipk，但风险更低、更干净。
