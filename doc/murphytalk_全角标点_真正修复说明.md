# murphytalk.pinyin 0.03 —— 全角标点「真正修复」说明

新包：**`murphytalk.pinyin_0.03_arm_noshiftzaoci_fwpunct.ipk`**
（含：关造词 + **按字符(unicode)判断的全角标点**。这次是从根上改对了。）

## 找到病根了（已用你的实测输出反证）

你反馈 space 左右的键出来是 `":;"'?/，，。。()`——我把它逐键复现，和「旧代码」的输出**一模一样**，因此确认：

> **老代码（包括上一版）判断标点时用的是「键码 keycode」，但这台机器上 Shift/Fn 组合键的键码不变、只有「字符 unicode」变。**

具体后果（这就是你看到的乱象）：
- `<`(Shift+`,`) 和 `,` **键码都是 0x2C** → 老表都映射成 ，→ 所以你看到 `，，`（本该 `，` 和 `《`）；`.`/`>` 同理都成了 `。`。
- `:`(Shift+`;`) 键码是 `;` 的 0x3B、`?`(Shift+`/`) 键码是 `/` 的 0x2F——**都不在老表覆盖的 0x2C–0x3F 命中点上** → 全部漏网、原样半角。
- `(` `)` 是 Shift+9 / Shift+0，**键码是数字 0x39/0x30** → 被当成「选第 9/0 个候选」，根本到不了标点逻辑 → 半角。

也就是说，老表里 `0x3a→：、0x3c→《、0x3e→》、0x3f→？` 这几项**永远不会被触发**（没有任何键送得出这些键码），而 `0x2c→，`、`0x2e→。` 又会被 Shift 组合「误触」。全乱。

## 这次怎么改（改对了）

改成 **按 unicode（真正打出来的字符）查表**，在 `GetKey` 入口最前面就拦一道：
- 把老的 `send_hanzi_mark` 整个改写成一个「unicode → 全角」的查表函数（表就放在它自己空出来的函数体里，没有增体积）；
- 在 `GetKey` 入口插一跳，先用 unicode 查表：命中就直接发全角、收工；没命中就照常走原来的拼音逻辑。
- 因为 unicode 就是「字符本身」（`<` 一定是 U+003C，跟哪个物理键、按没按 Shift 无关），所以这套判断**稳**，不像键码那样因机型而异。

只在**拼音模式**下转换；英文/直通模式（Tab 切的那个）里这些键仍是半角——正是中文输入法该有的样子。字母、数字、空格完全不受影响（拼音输入照旧）。

| 键 | 打出 | | 键 | 打出 |
|---|---|---|---|---|
| `,` | ， | | `[` | 【 |
| `.` | 。 | | `]` | 】 |
| `;` | ； | | `{` | ｛ |
| `:` (Shift+;) | ： | | `}` | ｝ |
| `?` (Shift+/) | ？ | | `(` (Shift+9) | （ |
| `!` (Shift+1) | ！ | | `)` (Shift+0) | ） |
| `<` (Shift+,) | 《 | | `\` | 、(顿号) |
| `>` (Shift+.) | 》 | | `~` | ～ |

**这次特意没转的**（保持半角），因为它们要么会误伤、要么需要「开/关引号」这种成对切换的状态：
- `'` `"` 单/双引号：中文引号 ‘’ “ ” 是**成对切换**的（前引号/后引号轮流），做死一个方向会一半是错的。要的话我可以再做一版带「开关状态」的引号；或者你接受「固定全角 ＇ ＂」也行——你说。
- `/`：留作半角（顿号 、我放在了 `\` 键上）。如果你更习惯 `/` 出顿号，我把它挪过去即可。

> 括号我这次用了中文书名式 `【 】`（比上版的 ［ ］ 更常用）。想要别的（比如 `「 」`『 』）随时说。
