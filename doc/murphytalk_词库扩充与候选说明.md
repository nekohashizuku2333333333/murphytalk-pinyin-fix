## 先说诊断：为什么会"打不出候选"

你确认了「能出候选、能选字」，所以引擎是好的。你遇到的两种情况，其实是**两个不同的原因**：

### 情况① 打单个字母（比如 `n`）不出候选
这是**老引擎的机制限制**，不是坏了：
- 这个 2004 年的引擎只认「**完整音节**」——它的单字表里只有 `a / ai / ba / ni / hao …` 这 410 个**完整音节**做键，**没有**「n」「zh」这种单声母键；
- 它匹配是「精确音节匹配」，**不支持"简拼/不完整拼音"**（现代输入法打 `n` 就出「你/您/能…」靠的正是简拼，这个老引擎没有这个功能）。

→ **这一条我没法安全修好**：要让它支持简拼，等于给引擎重写一套匹配算法（拆声母、模糊匹配），只能改二进制的核心逻辑，风险极高、极可能把输入法搞挂。我不建议冒这个险。老老实实打完整音节（`ni`、`hao`）就有候选。

### 情况② 打 `nihao` 这种词不出候选
这个**能修，而且已经修了**——原因很简单：**词库里根本没有「你好」这个词。**
- 引擎其实**会自动切分**：1 个音节 → 查单字；2 个以上音节 → 查**词库**。
- 但它 2004 年的词库虽然有「北京/我们/朋友」等一万条，却**恰好没有「你好」**，也没有大量现代常用词；而且查不到时它**不会退而求其次**去把第一个字（你）单独放出来。
- 所以 `nihao` → 切成 ni+hao → 查词库没有 → 什么都不出。

> 顺带提醒：**多音节词要连续打**（`nihao`），不要中间打空格。因为在这个输入法里**空格 = 选中第一个候选**，你打 `ni` 再打空格，其实是把「ni 的第一个候选」上屏了，然后才轮到 hao。

## 这次做了什么：给词库补了 1.5 万条常用词 ✅

- 数据来源：结巴(jieba)高频词表 + pypinyin 生成拼音（按引擎的拼写规则，比如 ü 写成 `v`：`女儿=nver`、`旅游=lvyou`），**逐词校验每个音节都在引擎认识的 410 个音节里**，不合格的直接丢掉。
- 只**追加**、不改动原有任何一条（**非破坏性**）；引擎加载时本来就会在内存里重新排序，所以追加是安全的。
- 已用「按引擎方式回读」的办法逐条校验：**22012 个词条、26949 条记录、0 错**；偏移、计数、UTF-8 全部对得上，原有词条（北京→北京/背景 等）原样保留。

现在这些都能出词了（举例）：
你好、谢谢、现在、手机、电脑、工作、学习、朋友、时间、问题、老师、医院、公司、城市、世界…（约 1.5 万条高频词）

装好后你打 `nihao` 就能直接出「你好」。

### 两个小提示
1. **启动会稍微慢一点点**：词库从 1 万条变成约 2.5 万条，输入法首次加载会多花一两秒（只在启动时）。如果你觉得太慢，告诉我，我把词数砍到 8000 左右。
2. **候选排序**：同一个拼音有多个词时（比如 `shouji` 有 收集/手机/首级），顺序按词频来，个别不一定是你最想要的排第一——用数字键选即可。想让某些词优先，也能调。

## 安装（覆盖之前那版）
```sh
# 备份（可选）
cp -r /home/zaurus/.murphytalk /home/zaurus/.murphytalk.bak
ipkg install -force-reinstall murphytalk.pinyin_0.03_arm_fwpunct_dict.ipk
# 重启 Qtopia（或注销重进）
```
> 覆盖安装会同时更新 `.so`、`murphytalk_phrase.dat`、`murphytalk_phrase_idx.txt` 三个文件；
> 你之前若在词库里加过自定义词，安装前记得备份（上面那条 cp 就是）。
