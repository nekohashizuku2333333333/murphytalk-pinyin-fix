# MurphyTalk Pinyin 解析与上屏路径分析

本文只记录当前源码中的执行路径，不提出新的代码修改。

## 1. 哪个函数决定拼音串怎么切成音节

有两层解析。

第一层是底层 SCIM 拼音键解析，位置在 `scim/scim_pinyin.cpp`：

- `PinyinKey::parse_initial()`：第 283-300 行，按 `scim_pinyin_initials[]` 查声母，选择最长匹配。
- `PinyinKey::parse_final()`：第 303-320 行，按 `scim_pinyin_finals[]` 查韵母，选择最长匹配。
- `PinyinKey::parse_key()`：第 334-370 行，先尝试零声母韵母，再尝试声母 + 韵母，最后处理声调。
- `PinyinKey::set_key()`：第 373-403 行，调用 `parse_key()`，如果 validator 不接受，则不断缩短长度重试。
- `PinyinKey::parse_pinyin_key()`：第 617-665 行，把连续字符串切成多个 `PinyinKey`。

`parse_pinyin_key()` 的旧实现不是现代意义上的全局回溯。它是从字符串尾部向前找一个能完整覆盖尾段的音节：

1. `key_end` 初始指向输入串末尾，第 629 行。
2. `key_start` 从 `key_end - SCIM_PINYIN_KEY_MAXLEN` 到 `key_end` 向右试，第 639-653 行。
3. 找到一个 `len == key_end - key_start` 的音节就接受，把 `key_end` 移到 `key_start`，第 644-649 行。
4. 如果找不到，就缩短整体 `keylen`，清空结果，从更短的尾部重新来，第 655-660 行。
5. 最后 `reverse()`，第 663 行。

所以它有“尾部最大可解析”的倾向，但不是完整动态规划，也不会保留多种切分候选。它会在失败时回退整体尾长，但一旦找到某段就接受，不会系统性枚举所有歧义路径。

第二层是本分支后来加在 `PinyinEngine.cpp` 的搜索层切分：

- `collect_pinyin_splits()`：第 146-196 行。
- `collect_mixed_splits()`：第 198-242 行。

`collect_pinyin_splits()` 是最长优先 DFS：

1. 从当前位置开始，第 146-148 行。
2. 最长尝试长度为 `SCIM_PINYIN_KEY_MAXLEN`，第 165-167 行。
3. 从长到短枚举候选音节，第 169 行。
4. 如果片段中含 `'`，不允许跨过去，第 170-178 行。
5. `PinyinKey::set_key()` 能完整消费该片段，且韵母不是空，就压入当前路径并递归，第 180-185 行。
6. 最多收集 16 条切分，第 150-151 行。

这一层有回溯，会保留多条切分，但它是在 `PinyinEngine::search()` 里用于查短语的上层逻辑，不是替换掉底层 `PinyinKey::parse_pinyin_key()`。

## 2. 未按选择键/空格/回车时哪里会上屏

当前直接上屏集中在 `PinyinFrame.cpp`。

真正发送按键给应用的是：

- `QPinyinFrame::SendKey()`：文件末尾附近，内部调用 `QWSServer::sendKeyEvent()`。

会调用 `SendKey()` 的主要位置：

- 英文模式直通：`filter()` 第 214-219 行。英文模式下除 Tab 外直接 `SendKey(unicode,keycode)`。
- 选中短语候选：`commit_selection()` 第 421-431 行，逐字 `SendKey(phrase[i].unicode())`。
- 选中单字候选：`commit_selection()` 第 435-441 行，调用 `SendKey(get_charunicode(index))`。
- 提交原始预编辑串：`commit_raw_preedit()` 第 455-460 行，逐字符 `SendKey(m_ime_info.pinyin[i])`。
- 中文标点：`GetKey()` 第 562-568 行。若有预编辑，先 `commit_preedit()`，然后 `SendKey(hanzi_mark)`。
- 退格且没有预编辑串：`GetKey()` 第 620-634 行，直接把退格发给应用。
- 未处理按键：`GetKey()` 后段会在 `!bKeyProcessed` 时 `SendKey(u,k)`，用于让输入法不认识的按键回到应用。

普通字母输入本身不会立即上屏：

- 字母分支在 `GetKey()` 第 577-581 行，只是把字符追加到 `m_ime_info.pinyin`，然后 `search()` 更新候选。

因此，和“新按键接不上当前音节”或“剩余串解析不了”相关的自动上屏点，不在字母分支，而在后续确认动作：

- 空格分支第 587-604 行会在有候选且满足条件时调用 `commit_preedit()`。
- 回车分支第 605-609 行调用 `commit_preedit()`。
- 数字分支第 571-575 行调用 `commit_selection(k)`。
- `commit_preedit()` 第 463-473 行：有候选时选第一个；无候选时调用 `commit_raw_preedit()`，把原始拼音串发给应用。

也就是说，如果某个输入串解析不了且没有候选，用户按回车时会走 `commit_raw_preedit()`，把拼音字母本身上屏。这是当前代码中“剩余串解析不了”后可能上屏字母的地方。

## 3. 输入串开头不是完整音节时，解析在哪一步返回空

底层单音节解析在 `PinyinKey::set_key()`：

- 空输入直接返回 0，第 378-380 行。
- 它调用 `parse_key()`，第 392 行。
- `parse_key()` 会先试韵母，再试声母 + 韵母，第 349-362 行。
- 对单独 `n`：`parse_final()` 得到空韵母，然后 `parse_initial()` 得到 `n`，但最终 `final` 仍为 `SCIM_PINYIN_ZeroFinal`。

如果只是 `set_key()` 本身，单独 `n` 并不一定返回 0；它可能返回长度 1，得到一个“声母 n + 空韵母”的 key。真正查不到字发生在单字表查找：

- `PinyinTable::find_chars()` 第 1147-1160 行。
- 它调用 `find_chars_with_frequencies()` 第 1153 行。
- 单字表里没有“声母 + 空韵母”的条目，所以返回 0。

本分支后面加入了专门的声母查找：

- `PinyinEngine::search()` 第 274-280 行：长度为 1 且是合法声母时，直接 `find_chars_by_initial()`。
- `PinyinTable::find_chars_by_initial()` 第 1184-1197 行。
- `PinyinTable::find_chars_by_initial_with_frequencies()` 第 1200-1218 行，会遍历单字表中所有该声母开头的完整拼音条目，汇总候选。

所以“开头不是完整音节时返回空”的老问题，不是 `parse_initial()` 不认识 `n`，而是常规单字查表路径只按完整 key 查，表中没有空韵母 key。

## 4. `hef` 执行路径追踪

以下按当前源码意图追踪。

### 输入 `h`

1. `GetKey()` 字母分支，第 577-581 行，把 `h` 加入 `m_ime_info.pinyin`。
2. 调用 `search()`。
3. `PinyinEngine::search("h")` 第 274-280 行命中单声母逻辑。
4. `get_initial_from_letter('h')` 返回 `SCIM_PINYIN_He`。
5. `find_chars_by_initial()` 返回 h 声母单字候选。
6. UI 只显示候选，未上屏。

状态：

- `m_ime_info.pinyin = "h"`
- `m_initial_lookup = true`
- `m_commit_pinyin_length` 默认是 1
- 候选为 h 声母单字

### 输入 `e`

1. `m_ime_info.pinyin` 变成 `"he"`。
2. `PinyinEngine::search("he")` 第 283-297 行先尝试整串完整音节。
3. `whole_key.set_key(..., "he", 2)` 成功，且韵母不是空。
4. `m_table.find_chars(..., he)` 返回“何/和/...”等候选。
5. `m_key.set_key("he")`，`m_commit_pinyin_length = 2`。
6. 返回候选。

状态：

- `m_ime_info.pinyin = "he"`
- `m_commit_pinyin_length = 2`
- 候选为 `he` 的单字

### 输入 `f`

1. `m_ime_info.pinyin` 变成 `"hef"`。
2. 整串完整音节检查第 283-297 行失败，因为 `hef` 不是完整音节。
3. `collect_pinyin_splits("hef")` 第 299-319 行尝试完整全拼多音节切分。
4. 如果查不到整词短语，继续往下。
5. 带空格混合输入分支第 321-365 行不进入，因为没有空格。
6. 连续混合简拼分支第 367-389 行可能尝试 `he + f` 或 `h + e + f` 这类模式；如果没有短语命中，继续往下。
7. 纯声母简拼分支第 391-400 行不会匹配，因为 `e` 不是声母。
8. `m_key.set_key("hef")` 第 403 行使用旧 `parse_pinyin_key()`。这里旧解析器有可能把它切成 `he + f` 或类似残缺形式，也可能只留下局部解析。
9. 如果进入多音节但短语查不到，当前兜底应该先走 `fallback_first_syllable_chars()` 第 438-440 行。
10. `fallback_first_syllable_chars()` 第 120-129 行内部调用 `append_first_syllable_chars()`。
11. `append_first_syllable_chars()` 第 101-117 行用 `first_key.set_key(..., "hef")` 取首个完整音节，应得到 `he`，设置 `m_mixed_char_commit_length = 2`。
12. 候选返回 `he` 的单字。

期望状态：

- `m_ime_info.pinyin = "hef"`
- 候选为 `he` 的单字
- 选择“何/和”等单字时，`get_commit_pinyin_length(global_index)` 应返回 2
- `commit_selection()` 第 443-445 行擦掉前 2 个字符，剩余 `f`

如果真机表现为“消费 h，留下 ef”，说明实际走到了首声母回退路径：

- `find_first_initial_chars()` 第 132-144 行返回 h 声母候选。
- `m_commit_pinyin_length = 1`，见第 443-444 或第 456-458 行附近的首声母回退设置。

这说明某条路径在首完整音节回退之前就返回了首声母候选，或者首完整音节回退没有成功。

## 5. `nma` 执行路径追踪

### 输入 `n`

1. `GetKey()` 字母分支追加 `n`。
2. `PinyinEngine::search("n")` 第 274-280 行命中单声母逻辑。
3. `find_chars_by_initial(n)` 返回 n 声母单字候选。

状态：

- `m_ime_info.pinyin = "n"`
- 候选为 n 声母单字
- 未上屏

### 输入 `m`

1. 输入串变成 `"nm"`。
2. 整串完整音节检查失败。
3. `collect_pinyin_splits("nm")` 很可能不能得到完整全拼切分。
4. 连续混合简拼 `collect_mixed_splits("nm")` 第 367-389 行可产生 `n + m`。
5. 如果短语表有 `n m` 对应短语，例如“你们”，则第 379-386 行返回短语候选，并追加首声母 `n` 的单字候选。

状态：

- 候选前部为短语，例如“你们”
- 后部为 `n` 的单字候选
- 选短语消费整个 `nm`
- 选后部单字消费 1 个字符，保留 `m`

### 输入 `a`

1. 输入串变成 `"nma"`。
2. 整串完整音节检查失败。
3. 全拼多切分通常失败。
4. 带空格分支不进入。
5. 连续混合简拼可能尝试 `n + ma`、`n + m + a`。如果短语表没有命中，继续。
6. 纯声母简拼失败，因为 `a` 不是声母。
7. `m_key.set_key("nma")` 走旧解析器。
8. 如果旧解析器没有有效 key，`!m_key.isValid()` 分支第 405-412 行会先尝试首声母回退。

这里的预期不是首完整音节，因为 `nma` 开头没有合法完整音节 `nm...`；`n` 只是声母，不是完整音节。因此应回退到首声母 `n`：

- `find_first_initial_chars()` 第 132-144 行。
- 设置 `m_initial_lookup = true`。
- 设置 `m_commit_pinyin_length = 1`。
- 返回 n 声母单字候选。

如果真机表现为 `nma` 无候选，说明当前执行路径没有落到第 405-412 行，或者 `find_first_initial_chars()` 没有被调用/没有返回候选。最可疑的位置是旧 `m_key.set_key("nma")` 返回了某种“有效但查不到字/词”的状态，随后进入了其他分支并返回 0，而没有再执行首声母兜底。

## 6. 小结

当前源码里影响这些问题的核心点有三个：

1. 底层 `PinyinKey::parse_pinyin_key()` 是从尾部向前找可解析片段，不是完整回溯；它可能产生和直觉不同的局部切分。
2. 上层 `PinyinEngine::search()` 叠加了完整音节优先、全拼 DFS、混合简拼、纯声母简拼、首音节回退、首声母回退多套规则；bug 往往来自这些规则的顺序。
3. 上屏只发生在 `commit_selection()`、`commit_preedit()`/`commit_raw_preedit()`、标点、英文直通和未处理按键直通；普通字母输入不会直接上屏。
