## ① 已完成：把左/右括号加进全角标点表 ✅（已打进新包）

现在在**拼音/中文模式下**，六个括号会输出全角：

| 按键 | keycode | 现在输出 | 码位 |
|---|---|---|---|
| `(` | 0x28 | （ | U+FF08 |
| `)` | 0x29 | ） | U+FF09 |
| `[` | 0x5B | ［ | U+FF3B |
| `]` | 0x5D | ］ | U+FF3D |
| `{` | 0x7B | ｛ | U+FF5B |
| `}` | 0x7D | ｝ | U+FF5D |

连同原有的 **，。：《》？**，一起走同一套「全角标点」逻辑。
（英文/直通模式下这些键仍是半角 `( ) [ ] { }`，不受影响——这正是中文输入法该有的行为。）

### 实现方式（干净、可回退）
- 利用上次 Shift 补丁**留下的死代码区**（`0x175a4`–`0x17604`，那段「进入造词」的代码在你上次改完后已经永远走不到）当作 code cave，没有新增体积、没有动任何常量池。
- 只在 `send_hanzi_mark` 入口插了一跳（`0x17124`）。
- 用到一个巧合：**全角 ASCII 括号 = 半角 + 0xFEE0**（`(`0x28+0xFEE0=0xFF08…六个都成立），所以不用查表、几条指令搞定。
- 相对你上传的包，**总共只改了 69 个字节**，全部落在死代码区 + 那一处入口跳转；`.so` 仍是合法 ARM ELF，符号链接 / 属主 / 权限原样保留。
- 已用反汇编器逐条复核跳转目标、并确认「活的常量池 `0x175c8`」未被碰到、Shift 补丁字节 `0x175a3=0xEA` 仍在。

### 关于括号样式（你可以选）
我默认用了「**全角 ASCII 形**」（（）［］｛｝），好处是形状忠实、一条 `+0xFEE0` 就能覆盖六个，最稳。
如果你更想要**中文书名/方头括号**风格，比如：
- `[` `]` → 【 】（U+3010/3011）
- `{` `}` → 「 」（U+300C/D）或 『 』（U+300E/F）

这个也能做，但因为它们不满足 `+0xFEE0` 的规律，需要另塞一小张常量表，属于另一版补丁。**告诉我你要哪种**，我再出一版即可。

## ② Fn+Space 出「abc」——诊断结论与建议做法

### 一句话结论
**这不是这个 .so 能可靠单独修好的东西。** 「按 Fn+Space 在输入法之间轮换」以及「有哪几个输入法参与轮换」，
是 **Qtopia 系统（qpe）** 在管的；「abc」是**系统另一套内置输入法**，不是这个拼音插件产生的。
我把整个插件从头到尾翻了一遍，它**没有任何识别「切换输入法键」的代码**，也没有 "abc" 之类字样。
所以要让「Fn+Space 开/关的始终是这个拼音」，正确的落点在**系统侧**，而不是继续改这个 ipk。

### 推荐的具体做法（低风险、可回退、不用改二进制）
思路：把参与 Fn+Space 轮换的那套内置「abc」输入法从插件目录里挪走，Fn+Space 就只会在
「MurphyTalk ↔ 关」之间切，不再冒出 abc。

**第一步（先别删，先看）——在 Zaurus 的终端里跑：**
```sh
ls -la /opt/Qtopia/plugins/inputmethods/
```
把结果发我。里面除了 `libmurphypinyin.so*`（就是本插件），
应该还有一到几个内置的，例如 `libkeyboard*`、`libpickboard*`、`libhandwriting*`、
`libunikeyboard*`、或名字里带 kbd/abc 的——那当中就有你看到的「abc」。

**第二步（确认后再动）——把那套内置的挪出目录（不是删，方便还原）：**
```sh
mkdir -p /home/zaurus/im_backup
mv /opt/Qtopia/plugins/inputmethods/libXXXX.so*  /home/zaurus/im_backup/
# 然后重启 Qtopia（或注销重进）
```
（`libXXXX` 换成第一步里确认的那套。挪错了随时 `mv` 回去即可，所以先别用 `rm`。）

> 我没法直接读你机器上的这个目录（这个会话连不到你的设备），所以**第二步的确切文件名要等你把第一步的 `ls` 结果发我**，我再逐个点名，避免挪错把输入搞没。

### 为什么不走「改 .so 拦截 Fn+Space」这条路
- 技术上**可以**：这个过滤器一装上就常驻、每个按键都经过它，理论上能在 `filter()` 里认出 Fn+Space、自己 show/hide 并把该键吞掉。
- 但它**必须知道 Fn+Space 在你这台机器上到底送出的按键码**——这个值在系统键盘映射里，不在 .so 里，从二进制推不出来。**猜错就会吞错键、甚至打不了字**，输入法这种东西我不想拿它赌。
- 而且 qpe 很可能在过滤器之前就把这个切换键截走了；那样再怎么改 .so 也没用。
- 相比之下，「挪走内置 abc」既达到你要的效果、又随时能还原，明显更稳。

如果你后面确实想要「Fn+Space 由插件自己接管」的版本，我们可以：先用一个**临时诊断版**把任意按键的 keycode 打成文字显示出来 → 你按一下 Fn+Space 读出那个码 → 我再据此出正式补丁。需要的话跟我说，我来做这个诊断版。
